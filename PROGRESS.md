## Этап 2A — вид «Библиотека» ✅ (этот коммит)

### Сделано

- **`books.html`** (корень проекта) — шапка «Библиотека» + подзаголовок,
  кнопка «← Главная» на `index.html`, переключатель темы (🌙/☀️).
  Подключает `css/base.css`, `css/reader.css`, `js/library.js`.
  Функции `initTheme()` / `toggleTheme()` — инлайн в странице, как в `index.html`
  (та же дупликация, что и везде в проекте; `localStorage` обёрнут в `try/catch`).
- **`css/reader.css`** — новый файл, неймспейс `lib-` для библиотеки
  (`rd-` зарезервирован под ридер, этап 2B). Только var()-токены из `base.css`,
  отдельная секция светлой темы, адаптив на 720 px и 420 px.
- **`js/library.js`** — IIFE-модуль `Library` (`init`, `load`, `openBook`),
  zero dependencies. `fetch data/books/index.json` → сетка карточек:
  обложка-эмодзи, `title` + `titleRu`, автор, бейдж уровня, «~9 мин»,
  число глав, прогресс-бар, счётчик собранных слов.
- **Прогресс** читается из `localStorage`: `dm_book_pos:<id>`,
  `dm_book_words:<id>`. Пока их никто не пишет → 0 % и «0 слов» —
  это нормальный путь, не ошибка.
- **Кнопка** «Читать» / «Продолжить» / «Читать заново» (при 100 %) →
  пока `console.log`, ридера нет.
- **Явные состояния**: загрузка (спиннер), ошибка (текст + причина +
  кнопка «Повторить»), пустой каталог (+ «Повторить»). Ни одного
  «глухого» `.catch(() => {})`: ошибки идут в `console.error` и на экран.

### Решения

- **Контракт `dm_book_pos:<id>`** зафиксирован здесь, писать его будет этап 2B.
  Чтение терпимое: `{ percent: 0..100 }` (приоритет) → `{ chapter, para }`
  (оценка `chapter / book.chapters`) → просто число как процент.
  Мусор и битый JSON → 0 % + `console.warn`.
- **`dm_book_words:<id>`**: массив слов, либо `{ words: [...] }`, либо
  объект-словарь — считается длина/число ключей. Гибкость нужна потому, что
  формат «сборника слов» определится на этапе 3.
- Проценты считаются **на клиенте при рендере**, ничего не кешируется:
  карточка всегда отражает актуальный `localStorage`.
- Карточки строятся строкой-шаблоном с `esc()`, обработчики навешиваются
  через `addEventListener` по `data-book-id` (без inline-`onclick`,
  в отличие от старых файлов — новый код, старую привычку не тащим).
- Файлы уроков не тронуты: `lesson-render.js`, 68 оболочек, `gen_template.html`,
  `css/lesson.css`, `css/exercises.css`, `flashcards.js` — без изменений.
- `?v=51` у новых ассетов проставлен вручную под текущую версию проекта;
  `bump_version.py`, `service-worker.js` и кнопка в сайдбаре — этап 5.

## Этап 2B — ридер: текст и пагинация ✅ (этот коммит)

### Сделано

- **`js/reader.js`** — IIFE-модуль `Reader` (`open`, `close`, `next`, `prev`,
  `goTo`, `repaginate`), zero dependencies. Отдельной страницы нет: ридер живёт
  в `books.html` как второй вид, переключение библиотека ↔ ридер без перезагрузки
  (`#libView` / `#rdView`, `body.rd-open`). Кнопка «Читать» из 2A вместо
  `console.log` вызывает `Reader.open(id)`.
- **Загрузка**: `meta.json` + `glossary.json` параллельно (`Promise.all`),
  затем `ch-NN.json` текущей главы. Глоссарий лежит в `st.gloss` и пока не
  используется — он нужен 2C, чтобы не дозагружать словарь по тапу.
- **Рендер**: слово → `<span class="bw" data-t="<lowercase>">`, предложение →
  `<span class="bs" data-p="i" data-s="j">`, пунктуация и пробелы — голый текст.
  Внутри span'ов никакого HTML. Перевод предложения в DOM не кладётся: 2C возьмёт
  его из `st.chapter` по `p`/`s`. У `.rd-content` стоит `lang="de"` — иначе
  переносы считались бы по правилам `lang="ru"` со страницы.
- **Пагинация** — CSS multi-column: `.rd-viewport { overflow: hidden }`,
  `.rd-content { column-width: W; column-gap: 32px; column-fill: auto; height: H }`,
  листание `transform: translateX(-page * (W + 32))` с переходом 180 мс,
  `pages = round(scrollWidth / (W + gap))`. Ручного замера высоты нет.
- **Позиция — якорь `{ chapter, p, s }`** (первое видимое предложение).
  Восстановление: найти `.bs[data-p][data-s]`, посчитать колонку через
  `offsetLeft / (W + gap)`, прыгнуть на неё. Номер страницы как позиция
  не хранится. В `localStorage` пишется `{ chapter, p, s, percent }` —
  формат из этапа 2A, карточка в библиотеке показывает реальный процент.
- **Панели**: верхняя — «назад», название главы + `titleRu`, «стр. 3 / 12»;
  нижняя — прогресс-бар главы, кнопки «‹ Назад» / «Вперёд ›» и пустой
  `#rdSlot` под кнопки 2C/2D.
- **Границы глав**: вперёд с последней страницы → следующая глава с первой;
  назад с первой → предыдущая глава на последней странице. Смежные главы
  заранее не грузятся. На концах книги кнопки блокируются.
- **Перепагинация** по `resize` и `orientationchange` (debounce 120 мс),
  без анимации, с сохранением якоря.
- **Состояния** загрузки и ошибки — явные, поверх вьюпорта, с «Повторить»
  и «В библиотеку»; на время состояния кнопки листания заблокированы.
  Ни одного `.catch(() => {})`.

### Проверено (headless Chrome, локальный `python -m http.server`)

Прогон из библиотеки кликами по реальным кнопкам, 360×640:

| Проверка | Результат |
|---|---|
| Геометрия | `scrollWidth` = 688 = `pages*(W+gap) - gap` при W=328, pages=2 — совпало точно |
| Страницы непустые | предложения распределились `{стр0: 5, стр1: 3}` |
| Разметка | `<span class="bw" data-t="es">Es</span>`, HTML внутри span нет, пунктуация вне span |
| Горизонтальный скролл страницы | отсутствует (`scrollWidth == clientWidth == 360`) |

| Сохранённая позиция | `{"chapter":2,"p":2,"s":4,"percent":69}` — без номера страницы |
| Возврат в библиотеку | карточка показала «69% прочитано» и «Продолжить» |
| Повторный вход | глава 3, «стр. 3 / 4», тот же якорь |
| Десктоп 1200×800 | колонка текста ограничена 720 px и центрирована, панели на месте |
| Тёмная и светлая тема | ок на 360×640 и на десктопе |
| Ошибка (книги нет) | «Книга не открылась», `data/books/nope/glossary.json: HTTP 404`, «Повторить» + «В библиотеку» |

Ограничение проверки: в headless с `--virtual-time-budget` CSS-переходы не идут,
поэтому анимация листания снята отдельным прогоном в реальном времени.
Свайпы не проверялись — их нет, это 2C.

### Решения и пойманные грабли

- **Якорь не перевыводится при перепагинации.** Первая версия после каждого
  resize брала «первое предложение страницы» — и позиция уезжала назад к началу
  главы (стр. 3/4 → 1/4 за три ресайза). Теперь `goTo` различает три случая:
  обычное листание (якорь = первое предложение новой страницы), восстановление
  (`opts.anchor`) и перепагинация (`opts.keepAnchor` — якорь читателя не трогаем).
- **`[hidden]` не работает при `display: flex`.** `.rd-view` и `.rd-state`
  перекрывали библиотеку и текст соответственно; добавлены явные
  `.rd-view[hidden]` и `.rd-state[hidden] { display: none }`.
- **Ширину для шага листания берём у `.rd-content`, не у вьюпорта**: у вьюпорта
  есть padding, и `clientWidth` давал бы шаг на 40 px больше реальной колонки.
- **Шрифты Google Fonts приезжают после первой пагинации** и меняют число
  страниц, поэтому после рендера главы висит `document.fonts.ready → repaginate()`.
- **Модули объявлены через `const`** — это лексический глобал, а не свойство
  `window`: перекрёстные проверки сделаны через `typeof Reader !== 'undefined'`
  (проверка `window.Reader` молча не срабатывала).
- Открытие ридера кладёт запись в `history` (`#book=<id>`), `popstate`
  возвращает в библиотеку — аппаратная кнопка «назад» в Telegram и PWA ведёт
  себя ожидаемо, а не выкидывает со страницы.
- Отдельного `reader.html` намеренно нет: один документ — одна загрузка
  ассетов и мгновенное переключение видов.
- Не тронуты: `lesson-render.js`, 68 оболочек, `gen_template.html`,
  `css/lesson.css`, `css/exercises.css`, `flashcards.js`, `tts.js`.
