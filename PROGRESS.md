- **Рендер**: слово → `<span class="bw" data-t="<lowercase>">`, предложение →

- **Пагинация** — CSS multi-column: `.rd-viewport { overflow: hidden }`,

  листание `transform: translateX(-page * (W + 32))` с переходом 180 мс,
  `pages = round(scrollWidth / (W + gap))`. Ручного замера высоты нет.
- **Позиция — якорь `{ chapter, p, s }`** (первое видимое предложение).
  Восстановление: найти `.bs[data-p][data-s]`, посчитать колонку через
  `offsetLeft / (W + gap)`, прыгнуть на неё. Номер страницы как позиция
  не хранится. В `localStorage` пишется `{ chapter, p, s, percent }` —
  формат из этапа 2A, карточка в библиотеке показывает реальный процент.
- **Панели**: верхняя — «назад», название главы + `titleRu`, «стр. 3 / 12»;
  нижняя — прогресс-бар главы, кнопки «‹ Назад» / «Вперёд ›» и пустой
  `#rdSlot` под кнопки 2C/2D.
- **Границы глав**: вперёд с последней страницы → следующая глава с первой;
  назад с первой → предыдущая глава на последней странице. Смежные главы
  заранее не грузятся. На концах книги кнопки блокируются.
- **Перепагинация** по `resize` и `orientationchange` (debounce 120 мс),
  без анимации, с сохранением якоря.
- **Состояния** загрузки и ошибки — явные, поверх вьюпорта, с «Повторить»
  и «В библиотеку»; на время состояния кнопки листания заблокированы.
  Ни одного `.catch(() => {})`.

### Решения и пойманные грабли

- **Якорь не перевыводится при перепагинации.** Первая версия после каждого
  resize брала «первое предложение страницы» — и позиция уезжала назад к началу
  главы (стр. 3/4 → 1/4 за три ресайза). Теперь `goTo` различает три случая:
  обычное листание (якорь = первое предложение новой страницы), восстановление
  (`opts.anchor`) и перепагинация (`opts.keepAnchor` — якорь читателя не трогаем).
- **`[hidden]` не работает при `display: flex`.** `.rd-view` и `.rd-state`
  перекрывали библиотеку и текст соответственно; добавлены явные
  `.rd-view[hidden]` и `.rd-state[hidden] { display: none }`.
- **Ширину для шага листания берём у `.rd-content`, не у вьюпорта**: у вьюпорта
  есть padding, и `clientWidth` давал бы шаг на 40 px больше реальной колонки.
- **Шрифты Google Fonts приезжают после первой пагинации** и меняют число
  страниц, поэтому после рендера главы висит `document.fonts.ready → repaginate()`.
- **Модули объявлены через `const`** — это лексический глобал, а не свойство
  `window`: перекрёстные проверки сделаны через `typeof Reader !== 'undefined'`
  (проверка `window.Reader` молча не срабатывала).
- Открытие ридера кладёт запись в `history` (`#book=<id>`), `popstate`
  возвращает в библиотеку — аппаратная кнопка «назад» в Telegram и PWA ведёт
  себя ожидаемо, а не выкидывает со страницы.
- Отдельного `reader.html` намеренно нет: один документ — одна загрузка
  ассетов и мгновенное переключение видов.
- Не тронуты: `lesson-render.js`, 68 оболочек, `gen_template.html`,
  `css/lesson.css`, `css/exercises.css`, `flashcards.js`, `tts.js`.

## Этап 2C — жесты и настройки чтения ✅ (этот коммит)

### Сделано

- **Жесты** — делегирование на `.rd-viewport`, capture-фаза, только Pointer
  Events (`pointerdown` / `pointerup` / `pointercancel`). Именно pointer, а не
  `touch` + `click`: иначе один тап листал бы дважды.
  - тап по левому полю (18 % ширины) → страница назад;
  - тап по правому полю (18 %) → страница вперёд;
  - тап по центру → скрыть/показать панели;
  - свайп по горизонтали (> 40 px, < 300 мс) → листание;
  - вертикальный свайп и медленное перетаскивание → игнор;
  - второй палец (`!e.isPrimary`) отменяет жест — пинч не листает.
  - кнопки поверх текста (состояние загрузки/ошибки) жестом не считаются.
- **Тап по слову** (`.bw`) выигрывает боковые зоны листания: страница не
  листается, слово оставлено под тултип этапа 3.
- **Кнопки «‹ Назад» / «Вперёд ›»** оставлены — на десктопе мышью удобнее.
- **Скрытие панелей** — только класс `.rd-chrome-hidden` на `.rd-view` →
  `opacity`, `transform`, `pointer-events`. Панели остаются в потоке, размеры
  `.rd-viewport` не меняются, перепагинации нет.
- **Настройки чтения** — bottom sheet (кнопка «Aa» в `#rdSlot`), сохраняются в
  `localStorage` под `dm_reader_prefs` = `{ fs, lh, theme, margin, font }`:
  - размер шрифта — 5 ступеней (15/17/19/21/23 px);
  - межстрочный интервал — 3 (1.5 / 1.75 / 2);
  - тема страницы — системная / сепия / тёмная;
  - поля — 3 ступени (12/22/38 px + ширина колонки 860/720/580 px);
  - шрифт — системный (DM Sans) / serif (Georgia).
  Ряды строятся из таблицы `SHEET_ROWS`, состояние — `aria-pressed`.
  Закрытие: крестик, тап по подложке, Esc.
- **Тема ридера не конфликтует с глобальной**: внутри ридера все цвета идут
  через свой слой `--rd-*`, объявленный на `.rd-view`. «Системная» наследует
  глобальные токены (`data-theme`), «сепия» и «тёмная» переопределяют `--rd-*`
  локально через `data-rd-theme`. Переключение `toggleTheme()` на странице
  сепию не ломает.
- **Любая смена настройки** → `repaginate()` с сохранением якоря (`keepAnchor`).

### Решения и пойманные грабли

- **Соседняя страница просвечивала в полосе `padding`.** `overflow: hidden`
  режет по padding-box вьюпорта, а не по колонке: при широких полях (38 px) и
  зазоре 32 px левый край следующей колонки попадал в кадр (замер: 9 «чужих»
  слов на странице при 320 px). Теперь зазор считается в `measure()`:
  `gap = max(32, боковое поле + 8)`, и число страниц берётся точной формулой
  `round((scrollWidth + gap) / (W + gap))` — при большом зазоре на десктопе
  простое `round(scrollWidth / (W + gap))` ошибается на страницу.
- **Якорь теперь по слову, а не по предложению**: `{ chapter, p, s, w, percent }`.
  Длинное предложение занимает несколько страниц, и «первое предложение
  страницы» на таких страницах указывало на колонку назад — переход «назад в
  предыдущую главу» открывал стр. 3/4 вместо 4/4, а каждая перепагинация
  отбрасывала на страницу раньше. Поле `w` — дополнение к контракту из 2A;
  старые позиции без `w` читаются как раньше (падение до `.bs`).
- **Перепагинация после смены настройки — синхронно, без
  `requestAnimationFrame`.** В невидимой вкладке кадры не идут, и пересчёт
  отставал на один шаг (размер шрифта менялся, а страницы оставались старыми).
  `measure()` читает `clientWidth`/`scrollWidth`, а чтение форсирует layout с
  новыми переменными — этого достаточно. Второй проход остаётся на
  `document.fonts.ready` (переключение на serif и обратно).
- **Тап по слову в центре переключает панели.** Текст занимает почти весь
  центр, и если бы слово «съедало» и центральный тап, жест «скрыть панели» был
  бы недоступен. Слово выигрывает только боковые зоны листания. В этапе 3
  тултип перехватит центральный тап по слову раньше.
- **Шторка и подложка показываются классом `.show`, без атрибута `hidden`** —
  чтобы снова не наступить на `display: flex` против `[hidden]` (грабли 2B).
- Не тронуты: `lesson-render.js`, 68 оболочек, `gen_template.html`,
  `css/lesson.css`, `css/exercises.css`, `flashcards.js`, `tts.js`.

### Решения и пойманные грабли

- **Ширина тултипа зависела от собственного `left`.** Тултип — shrink-to-fit
  между `min-width` и `max-width`: при большом `left` справа мало места и текст
  переносится иначе. Измерение шло до клампинга, поэтому ширина занижалась и
  правый край уезжал за экран — 10 слов из 96 на 360 px. Теперь перед замером
  `left` ставится в минимум (места максимум), и только потом считается позиция.
  Это же объясняет второй проход `positionWordTip` через rAF в уроках.
- **Закрытие «тапом вне» не должно листать.** Свой слушатель `pointerdown`
  в `ReaderTip` закрывал тултип раньше, чем жестовый слой ридера успевал
  увидеть его открытым на `pointerup` — тап по боковой зоне закрывал тултип
  **и** перелистывал страницу. Слушатель теперь не трогает тапы внутри
  `.rd-viewport`: там решение принимает ридер и тап «съедается».
- **`.word-tip--book` получил `pointer-events: auto`** (в базовом классе
  `none`): иначе тап проходил бы сквозь тултип на текст под ним, а в этапах 4
  и 3C там появятся кнопки.
- Тултип позиционируется по `offsetWidth/offsetHeight`, а не по
  `getBoundingClientRect`: у скрытого тултипа стоит `scale(.98)`, и rect
  занижал бы размеры на 2 %.
- `.bw.word-tip-open` подсвечивается акцентом ридера — это отклик на тап,
  а не «подсветка слов» из 3B.
- `css/lesson.css` подключён в `books.html` целиком: все его селекторы
  классовые и привязаны к разметке урока (`.lesson-*`, `.phrase-*`,

## Этап 4A — onEnd в js/tts.js ✅ (этот коммит)

Ридер не тронут: в этом этапе менялся только `js/tts.js`, чтобы очередь чанков
на этапе 4B строилась на событии завершения, а не на оценке длительности.

### Сделано

- **`TTS.speak(text, opts)` принимает `opts.onEnd`** — колбэк вызывается
  **ровно один раз** с `{ ok, reason }`:

  | reason | когда |
  |---|---|
  | `end` | нормальное завершение (`ok: true`) |
  | `interrupted` | прервано новым `speak()` или `TTS.stop()` (`ok: false`) |
  | `error` | голос заговорил и сломался (`ok: false`) |
  | `no-audio` | все источники `<audio>` молчат (`ok: false`) |
  | `empty` | озвучивать нечего, текст пустой (`ok: false`) |
  | `timeout` | сработала аварийная страховка (`ok: true`) |

- **Один вызов `speak()` = одна сессия** (`newSession`). Каскад
  `speechSynthesis → Web Audio → <audio>` сессию не закрывает: `onEnd`
  отдаётся на итоговом исходе, а не на каждом шаге каскада. Реализовано
  во всех трёх ветках:
  - `speechSynthesis` → `utterance.onend` (+ флаг `abandoned`: если ушли на
    аудио-путь по таймауту или ошибке, `onend` от `cancel()` игнорируется —
    иначе сессия закрылась бы раньше времени);
  - Web Audio → `source.onended` (рядом с прежним сбросом `currentSource`);
  - `<audio>` → `addEventListener('ended')`; элемент синглтон, поэтому
    слушатель ровно один и снимается в `finish()` / `stopCurrent()`.
- **Аварийная страховка**: если событие завершения не пришло за
  `(300 + букв × 70) × 1.6` мс — `onEnd` вызывается принудительно с
  `reason: 'timeout'`. Когда реальная длительность известна (буфер Web Audio,
  `<audio>.duration`), окно расширяется до `max(база, длительность × 1.6 + 500)`
  — чтобы страховка не срабатывала раньше конца длинной фразы. Это именно
  страховка: в норме её снимает событие.
- **`TTS.stop()`** — останавливает текущее воспроизведение (тот же
  `stopCurrent`) и отдаёт `onEnd` с `{ ok: false, reason: 'interrupted' }`.
- `speakPhrase(text, spans, opts)` и `speakSlow(text, opts)` прокидывают
  третий/второй аргумент в `speak` — понадобится ридеру.

### Обратная совместимость

Без `onEnd` сессия не делает **ничего**: ни таймера страховки, ни слушателя
`ended` (`arm()` и `attachEnded()` выходят сразу, если колбэка нет). Старые
вызовы идут прежним путём.

  `progress` / `sections` / `lastLesson`; `dm_progress` не тронут. Формат:
  `{ <bookId>: { pos: {...}, words: { <лемма>: {...} } } }` — собирается из
  `dm_book_pos:*` и `dm_book_words:*`.
- Слияние (рядом с `_mergeGlobal`, но отдельными функциями, чтобы книги
  не попадали в `dm_progress`): позиция — **last-write-wins по `ts`**
  (запись без `ts` считается самой старой); слова — **union по лемме**,
  `n = max`, `seen` — объединение форм без дублей по регистру, **`known`
  побеждает `new`**, `ts = max`, `ch`/`p` (первая встреча) остаются
  локальные. Вызывается из `importAll`.
- `js/reader.js`: в `dm_book_pos:<id>` добавлено поле **`ts`** — без него
  last-write-wins не имел бы опоры.
- `api/webhook.py`: узкая ветка `_merge_books` при записи — остальной снимок
  по-прежнему перезаписывается входящим. Ценой одного лишнего `GET` на
  запись: иначе клиент без поля `books` (старая версия) стёр бы чтение,
  накопленное на другом устройстве.

### 2. Кнопка «🃏 карточки (N)» в `#rdSlot` — область ГЛАВА

Выбрана глава, не страница. На 360×640 глава занимает две страницы, а на
десктопе умещается в одну («стр. 1 / 1»): привязка к странице означала бы
на каждом устройстве своё — то три слова, то вся глава, и N прыгал бы
под пальцем на каждом листании. Глава от ширины экрана не зависит и
совпадает ровно с тем, что читатель видит подсвеченным в тексте.

`N` = число различных лемм, которые собраны, ещё активны (`status !== 'known'`)
и встречаются в DOM текущей главы. `N = 0` → кнопка `disabled`.
Пересчёт живёт в `markLemma()` — любая смена пометки меняет и набор
активных слов, поэтому счётчик не отстаёт даже внутри сессии карточек.

Словарь книги — отдельной кнопкой 📗 в `.rd-top`: четвёртая кнопка в
нижний слот на 360 px уже не влезала.

  неправильной словарной форме. Оборот: перевод, часть речи,
  формы/склонение, «устар.» если есть.
- Тап по карточке — переворот; 🔊 на обеих сторонах (`stopPropagation`,

  карточки в DOM, а не из индекса: после возврата в конец очереди порядок
  меняется, и индекс разъехался бы.

### 4. Словарь книги

Полноэкранный вид, открывается из ридера (📗) и с карточки книги в
библиотеке. Поиск по слову, переводу и встреченным формам; фильтр

всегда совпадает со списком); экспорт в текст.

- Тап по слову — **тот же `ReaderTip`**, что в ридере. Глоссарий ему
  собирается из самой записи сборника: в словаре глава может быть не
  загружена, а вся грамматика уже лежит в записи.

### 10.2 Озвучка режется по границе страниц (этот коммит)

**Отмена решения 8.1.** Там разорванное предложение читалось целиком со
страницы, где лежит его **большая часть**. Это не решало задачу в
принципе: меньшая часть всё равно оставалась невидимой — пользователь
по-прежнему слышал текст, которого не видит, просто реже.

**Сначала проверено, работает ли сам переход.** Прогон `ch-03` с первой
страницы, замер `Reader.state.page` до и после `onItem` на каждом
предложении:

| предложение | page до onItem | page после goTo | через 300 мс | колонки |
|---|---|---|---|---|
| p1.s0 | 0 | 1 | 1 | {1: 17} |
| p2.s1 | 1 | 2 | 2 | {1: 10, 2: 13} |
| **p3.s1** | **2** | **3** | **3** | **{2: 10, 3: 32}** |

Переход **работал**: на `p3.s1` страница 2 → 3, `transform` доехал до
−1044 px. Отдельного бага не было — ошибочной была сама постановка.

**Сделано.**

- **`sentenceParts(bs)`** (заменил `pageOfSentence`) режет **текст**
  предложения по границе колонок. Смещения берутся из DOM: `.bs`
  отрисован из того же `sent.de`, поэтому `bs.textContent` совпадает с
  ним символ в символ. Если вдруг не совпало — отдаётся одна часть
  целиком: лучше прежнее поведение, чем потерянный кусок текста.
- **Рез — ровно перед первым словом новой колонки.** Всё, что лежит
  между словами (пробел и знаки препинания), остаётся с предыдущей
  частью, а слово не рвётся никогда.
- **Очередь идёт частями, а не предложениями.** Предложение на одной
  странице даёт одну часть, разорванное — по части на страницу. Внутри
  части работает прежний `chunkForTts` с лимитом прокси в 200 символов.
- Перед каждой частью `onItem` уходит на её страницу тем же `goTo`
  (не `next()`: `next()` — жест читателя и обязан обрывать чтение).
  Пауза на стыке совпадает с перелистыванием.
- **`.bs--playing`** по-прежнему красит предложение целиком. Поверх него
  `.bw--speaking` отмечает именно ту часть, что звучит, — но только когда
  частей больше одной. Как и все подсветки ридера, только цвет и фон:
  метрики строки не меняются, пагинация поехать не может.

**Проверено** (360×640, все четыре главы, настоящий прогон озвучки с
заглушкой `TTS`; замер через 280 мс после `onItem`, когда анимация

Все **восемь** разорванных предложений книги:

а не ошибка нарезки, и замер теперь считает такие слова отдельной
колонкой, а не «невидимыми».

## Этап 11 — обновление приложения: почему телефон держал старый код ✅ (этот коммит)

**Повод.** На десктопе новая версия (кнопка «дальше»), на телефоне старая.
Пользователь удалил PWA и чистил кэш — не помогло.

### Диагностика: прод был здоров

Качал с Pages, не с диска:

| Проверка | Результат |
|---|---|
| `books.html` → все `?v=` | **58**, единственное значение |
| `service-worker.js` → `CACHE` | **`deutsch-meister-v73`** |
| `js/reader.js` → вхождений `sentenceParts` | **4** |
| `books.html` → кнопка «дальше» | есть |
| Все 27 адресов из `STATIC` | **200**, ни одного 404 |

Значит **не деплой**. Заголовки тоже не виноваты: GitHub Pages отдаёт
`Cache-Control: max-age=600` (десять минут, а не год) с `ETag` и
`Last-Modified`.

### Три дырки в нашем коде

1. **`books.html` не регистрировал воркер вообще.** `register()` — это и
   есть то, что заставляет браузер проверить обновление. Читалку
   открывают прямо по ссылке, и на ней проверка не запускалась **никогда**:
   страница управлялась старым воркером и не имела способа его сменить.
   Регистрация была только в `index.html` и в 68 оболочках уроков.
2. **`register()` шёл без `updateViaCache: 'none'`.** По умолчанию
   (`'imports'`) браузер берёт сам файл воркера из HTTP-кэша, а он на
   Pages живёт 600 секунд, — «проверка обновления» до десяти минут
   смотрит в копию.
3. **Установка воркера могла провалиться навсегда.** `install` делал
   `caches.addAll(STATIC)`, и `skipWaiting()` висел на `.then()` после
   него. `addAll` отклоняется **целиком**, если хотя бы один URL не
   отдался: один битый адрес или моргнувшая сеть — и новый воркер не
   активируется никогда, старый продолжает отдавать старые файлы.
   Пользователь такое не чинит ни удалением PWA, ни очисткой кэша:
   «очистить кэш» в Android Chrome не снимает регистрацию воркера и не
   трогает Cache Storage.

Плюс четвёртое, не баг, но причина слепоты: **номер версии нигде не
показывался**. «У меня старая версия» нельзя было ни подтвердить, ни
опровергнуть.

### Сделано

- **`js/sw-register.js`** — одна регистрация на все страницы:
  `updateViaCache: 'none'`, `reg.update()` при загрузке **и при каждом
  возврате на вкладку** (открытая неделями PWA иначе не проверяется
  вовсе), немедленная активация ждущего воркера, одна перезагрузка по
  `controllerchange`. Инлайновый блок из `index.html` уехал сюда целиком.
- **Защита от цикла перезагрузок**: счётчик в `sessionStorage`, не более
  двух подряд; через десять секунд жизни страницы счётчик обнуляется,
  чтобы следующее честное обновление в той же сессии не упёрлось в лимит.
- **`books.html` подключает `sw-register.js`** — дырка №1 закрыта.
- **`service-worker.js`**: `skipWaiting()` теперь **первым делом**, до
  прекеша; каждый файл кладётся отдельно (`c.add(url).catch(...)`), и его
  неудача не роняет остальные. Прекеш — оптимизация для офлайна, а не
  условие работы. `message` принимает и строку `'SKIP_WAITING'`, и
  `{type:'SKIP_WAITING'}`: старая страница обязана уметь разбудить новый
  воркер.
- **Строка версии** — в подвале библиотеки (`.lib-foot`) и в шторке
  настроек ридера. Номер берётся из `?v=` собственного тега `<script>`:
  `bump_version.py` правит его во всех HTML, значит отдельного места для
  версии заводить не нужно и рассинхрону взяться неоткуда.
- **Аварийный сброс** `dmHardReset()` — кнопка «⟳ Обновить приложение» в
  настройках ридера: снимает **все** регистрации, сносит **все** кеши,
  перезагружает. Со страховочным таймером на 3 секунды, если какой-то шаг
  завис. `location.reload(true)` не используем — параметр `forceGet`
  давно игнорируется, а после `unregister` + `caches.delete` отдавать
  старое уже некому.

### Пойманное по ходу

- **`caches.open()` падал не из-за headless.** В 5B было записано, что в
  этом окружении Cache Storage не работает и потому воркер приходилось
  проверять в Node-песочнице. На самом деле дело в **пути профиля**:
  с `--user-data-dir` внутри `AppData\Local\Temp` `caches.open()` даёт
  `UnknownError: Unexpected internal error`, а с профилем вне Temp
  (`C:\Users\<user>\dm-chrome-hl`) всё работает — и в headless тоже.
  Ограничение 5B снято: воркер теперь проверяется в настоящем браузере.
- **`unregister()` не удаляет регистрацию, пока открыт её клиент.**
  Первые прогоны не воспроизводили «залипание»: после чистки старый
  воркер регистрировался, но новый `books.html` тут же забирал scope
  обратно. Лечится уходом на нейтральную страницу между чисткой и
  установкой старого воркера.

### Известное ограничение

68 оболочек уроков регистрируют воркер своим инлайновым однострочником
**без** `updateViaCache: 'none'` — править их нельзя. Заход на урок
вернёт регистрации значение `'imports'`, и следующая проверка воркера
может до десяти минут смотреть в HTTP-кэш. Любой заход на главную или в
библиотеку ставит `'none'` обратно. Дырку №1 (отсутствие регистрации)
это не воскрешает: уроки воркер регистрируют, то есть проверку запускают.
